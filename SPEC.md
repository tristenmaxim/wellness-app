# Spec: Wellness — подсчёт калорий по фото

Status: Draft
Author: Tristen Maxim
Date: 2026-08-24
Last updated: 2026-08-24

## Problem

Ручной подсчёт калорий (взвешивание еды, поиск в базах продуктов) — главный барьер, из-за которого люди бросают трекинг питания в первую неделю. Нужен способ занести приём пищи за секунды: сфотографировал — получил ккал/БЖУ.

## Goals

- Занесение приёма пищи занимает < 15 секунд (фото → результат)
- Распознавание еды по фото с приемлемой точностью для бытового трекинга (не для мед. назначений)
- Пользователь может вести дневник питания и видеть прогресс к цели без сторонних приложений

## Non-goals (explicit out of scope)

- Медицинская точность подсчёта (не заменяет диетолога/врача)
- Монетизация, подписки, платные лимиты — в этой версии всё бесплатно
- Web-регистрация email/пароль или OAuth Google/Apple — авторизация только через Telegram
- Социальные функции (друзья, лента, сравнение с другими)
- Android/iOS нативные приложения — только PWA

## Users

**Primary:** Человек, который хочет считать калории без рутины ручного ввода — открывает Telegram, фотографирует еду, получает цифры.
**Secondary:** Пользователь, который иногда предпочитает ввести приём пищи текстом (когда фото сделать неудобно или еда уже съедена).

## User stories

- Как пользователь, я хочу сфотографировать еду и сразу увидеть ккал/Б/Ж/У, чтобы не искать продукт в базе вручную.
- Как пользователь, я хочу ввести приём пищи текстом («омлет из 2 яиц»), чтобы занести данные, когда фото недоступно.
- Как пользователь, я хочу видеть дневник питания за день/неделю, чтобы понимать, сколько уже съел.
- Как пользователь, я хочу задать целевые ккал/БЖУ (похудение/набор/поддержание), чтобы видеть прогресс к цели, а не голые цифры.
- Как пользователь, я хочу войти одним нажатием через Telegram, чтобы не создавать отдельный аккаунт.

## Solution overview

PWA-приложение, открывается из Telegram-бота (Telegram Mini App / WebApp) — авторизация происходит через `initData` Telegram WebApp API, отдельного логина/пароля нет. Внутри приложения пользователь либо фотографирует еду камерой устройства, либо вводит блюдо текстом. Фото/текст уходит на бэкенд, бэкенд обращается к Gemini Flash через OpenRouter с промптом на структурированный разбор блюда (список продуктов, вес, ккал, белки/жиры/углеводы). Результат показывается пользователю с возможностью поправить вес/порцию перед сохранением в дневник. Дневник — список приёмов пищи по дням с суммарными ккал/БЖУ и сравнением с дневной целью (прогресс-бар/кольцо).

Основные экраны: (1) главный — сегодняшний прогресс + кнопка добавить приём пищи, (2) добавление — фото/текст → результат распознавания → подтверждение, (3) дневник — история по дням, (4) цели — ввод/редактирование целевых ккал/БЖУ, (5) профиль — базовая инфа из Telegram (имя, аватар).

## Detailed requirements

### Functional requirements

| ID | Requirement | Priority |
|---|---|---|
| F1 | Авторизация через Telegram Mini App (валидация `initData` на бэкенде) | P0 |
| F2 | Загрузка/съёмка фото еды и отправка на распознавание | P0 |
| F3 | Распознавание блюда через Gemini Flash (OpenRouter): список продуктов, вес, ккал, Б/Ж/У | P0 |
| F4 | Ручной ввод приёма пищи текстом с тем же LLM-разбором | P0 |
| F5 | Подтверждение/корректировка результата перед сохранением (изменить вес порции, убрать/добавить позицию) | P0 |
| F6 | Дневник питания: список приёмов пищи по дням, суммарные ккал/БЖУ за день | P0 |
| F7 | Постановка цели (целевые ккал и/или Б/Ж/У на день) | P0 |
| F8 | Отображение прогресса за день (съедено / цель) | P0 |
| F9 | Просмотр истории за прошлые дни | P1 |
| F10 | Редактирование/удаление ранее сохранённого приёма пищи | P1 |
| F11 | Офлайн-доступ к уже загруженному дневнику (PWA, service worker кеш) | P2 |
| F12 | Push-уведомление через Telegram-бота с напоминанием занести приём пищи | P2 |

### Non-functional requirements

- **Performance:** ответ на фото (загрузка → результат LLM) — p95 < 8 секунд
- **Security:** валидация Telegram `initData` (hash-проверка) на каждый запрос; OpenRouter API-ключ только на бэкенде, не в клиентском коде; фото хранятся с привязкой к user_id, без публичного доступа
- **Availability:** без формального SLA на MVP; сервис не должен падать целиком при недоступности OpenRouter — деградация с понятной ошибкой пользователю
- **Scalability:** MVP рассчитан на личное/небольшое использование (десятки-сотни пользователей), без требований к горизонтальному масштабированию

## Edge cases & error states

| Scenario | Expected behavior |
|---|---|
| LLM не может распознать еду на фото (нечёткое фото, не еда) | Показать сообщение «не удалось распознать», предложить ввести текстом вручную |
| OpenRouter/Gemini недоступен или таймаут | Показать ошибку, разрешить повтор запроса, приём пищи не сохраняется молча |
| Пользователь открыл приложение вне Telegram (напрямую по URL) | Показать экран «откройте через Telegram-бота» вместо приложения |
| Текстовый ввод неоднозначен («что-то на ужин») | LLM просит уточнение или возвращает приблизительную оценку с пометкой «примерно» |
| Пользователь редактирует вес порции после распознавания | Ккал/БЖУ пересчитываются пропорционально на клиенте или повторным запросом к LLM |
| Нет интернета при открытии дневника | Показ закешированных данных (PWA offline), пометка «данные могут быть неактуальны» |
| Цель не задана, а пользователь смотрит прогресс | Показывать только съеденное за день без прогресс-бара, с призывом задать цель |

Все закрыты (2026-08-24):

- **LLM + база продуктов:** LLM разбирает блюдо на позиции, каждая позиция сверяется с USDA FoodData Central (уточнение ккал/БЖУ по эталонной базе). Если позиция не находится в базе — остаётся LLM-оценка с пометкой «примерно».
- **Фото:** хранится и фото, и результат разбора (для истории и возможности пересчёта/повторной проверки).
- **Лимиты запросов:** без лимитов на MVP.
- **Стек:** см. раздел ниже.

## Технический стек (предложение)

- **Frontend:** React + TypeScript + Vite, `vite-plugin-pwa`. UI поверх Telegram WebApp JS SDK (тема, кнопки, `initData`).
- **Backend:** Python + FastAPI. Один сервис, без микросервисов — нагрузка не требует разделения.
- **БД:** PostgreSQL — пользователи, приёмы пищи, позиции блюда, цели.
- **Хранилище фото:** локальный диск на VPS (том Docker), без внешнего S3 — трафик и объём малы для MVP.
- **LLM:** OpenRouter → `google/gemini-flash-*`, вызов напрямую через HTTP (без SDK-обвязки).
- **Сверка нутриентов:** USDA FoodData Central API (бесплатный, по API-ключу).
- **Auth:** Telegram Mini App — валидация `initData` (HMAC-SHA256 бот-токеном) на каждый запрос, отдельных сессий/паролей нет.
- **Деплой:** Docker Compose (backend + Postgres + nginx) на 146.103.109.188, nginx-конфиг под `wellness.maxtristen.com` + Let's Encrypt (certbot).

## Dependencies

- OpenRouter — API-ключ для доступа к Gemini Flash (ожидается от пользователя)
- Telegram Bot API — токен бота для Mini App и авторизации (ожидается от пользователя)
- Хостинг: сервер 146.103.109.188, домен wellness.maxtristen.com (DNS через Porkbun) — доступ подтверждён, поддомен пока не настроен в nginx

## Репозиторий и CI/CD

- Репозиторий: [github.com/tristenmaxim/wellness-app](https://github.com/tristenmaxim/wellness-app) (публичный)
- CI/CD: GitHub Actions (`.github/workflows/deploy.yml`) — build-проверка на каждый push/PR, деплой на `/opt/wellness` на 146.103.109.188 при push в `main` (rsync + `docker compose up -d --build`)
- SSH-доступ CI отдельным ключом (не личным), добавлен в `root@146.103.109.188:~/.ssh/authorized_keys`

- Не выставлены (ждут от пользователя): `OPENROUTER_API_KEY`, `TELEGRAM_BOT_TOKEN`, `USDA_API_KEY`
